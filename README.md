# Tools API SDK

The PHP SDK for interacting with the VHosting Tools API, developed using the [Saloon](https://saloon.dev/) library.

## Installation

You can install the package via composer:

```bash
composer require vhosting/tools-sdk
```

The package automatically registers itself in Laravel through the Service Provider.

## Configuration

You can publish the configuration file with the following command:

```bash
php artisan vendor:publish --provider="VHosting\ToolsSdk\ToolsSdkServiceProvider"
```

These are the supported environment variables:

```env
TOOLS_TOKEN=your-api-token
TOOLS_URL=https://tools.vhosting-it.com
TOOLS_MOCK=false
```

The token can be generated by visiting [https://tools.vhosting-it.com/token](https://tools.vhosting-it.com/token).

## Usage

The SDK provides a Laravel Facade that makes it easy to access resources.

### Workflow Management

All workflow operations are accessible via `ToolsSdk::workflow()`.

#### Retrieve all workflows (Paginated)

```php
use VHosting\ToolsSdk\Facades\ToolsSdk;

$paginator = ToolsSdk::workflow()->all();

foreach ($paginator as $workflow) {
    echo $workflow->id;
    echo $workflow->status;
}
```

#### Retrieve a single workflow

```php
$workflow = ToolsSdk::workflow()->get(123);

echo $workflow->description;
echo $workflow->tasks_count;
```

#### Dispatch a new workflow

```php
$workflow = ToolsSdk::workflow()->dispatch('workflow-type-name', [
    'parameter1' => 'value1',
    'parameter2' => 'value2',
]);

echo $workflow->id;
```

#### Retry a failed workflow

```php
ToolsSdk::workflow()->retry(123);
```

### Proxmox Firewall

```php
$firewall = ToolsSdk::proxmox()->vm(123)->firewall();

$rules = $firewall->rules;
$ipset = $firewall->ipset;
$options = $firewall->options;
```

Rules and options are returned as `FirewallRule` and `FirewallOption` objects.

Use `firewallRules()` to create a rule or change an existing rule by its current `pos`.

```php
$rules = ToolsSdk::proxmox()->vm(123)->firewallRules();
$rules->store(['type' => 'in', 'action' => 'ACCEPT', 'proto' => 'tcp', 'dport' => '443']);
$rules->update($pos, ['comment' => 'Allow HTTPS']);
$rules->destroy($pos);
```

Create or update an IP set with an optional comment or new name.

```php
$vm = ToolsSdk::proxmox()->vm(123);
$vm->firewallUpsertIpset('allowed', ['comment' => 'Office networks']);
$vm->firewallUpsertIpset('allowed', ['rename' => 'trusted']);
```

Retrieve the content of an IP set as an array of `FirewallIpset` objects:

```php
$entries = ToolsSdk::proxmox()->vm(123)->firewallIpset('allowed');

foreach ($entries as $entry) {
    echo $entry->cidr;
    echo $entry->comment;
}
```

### Proxmox Kickstart

```php
use VHosting\ToolsSdk\Types\Proxmox\KickstartType;

$kickstart = ToolsSdk::proxmox()->vm(123)->kickstart();

$configuration = $kickstart->show();

$configuration = $kickstart->upsert(
    enabled: true,
    type: KickstartType::UbuntuAutoInstall,
    content: "#cloud-config\nautoinstall:\n  version: 1\n",
);

$configuration = $kickstart->upsert(
    enabled: false,
    type: $configuration->type,
    content: $configuration->content,
);

$kickstart->destroy();
```

All three fields are required when creating or updating a configuration.

## Mocking for Tests

The SDK integrates Saloon's faking system to facilitate testing:

```php
use VHosting\ToolsSdk\Facades\ToolsSdk;
use Saloon\Http\Faking\MockResponse;

ToolsSdk::fake([
    '*' => MockResponse::make(['id' => 1, 'status' => 'completed'], 200),
]);
```

It is also possible to enable mocks globally via the `TOOLS_MOCK=true` environment variable, which will use the default data defined in the `Mocks` class.
